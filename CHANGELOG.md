### Changed - Phase 1: Operational Stability, Startup Integrity & Immediate Security Quick Wins
- Step 1.1: [AUD-OPS-001] Implemented serverless-aware bounded MongoDB connection pool sizing in `backend/config/db.js` defaulting to 1 connection in production/serverless (protecting Atlas limits against concurrent invocations), 10 in development, and respecting explicit bounds `[1, 100]`.
- Step 1.2: [AUD-OPS-002] Implemented fail-fast server startup bootstrapping via `startServer()` in `backend/server.js` ensuring connection resolution before listening, fatal termination on unreachable DB, and mounted `trust proxy` for reverse proxy client IP resolution.
- Step 1.3: [AUD-OPS-004] Implemented fail-fast startup environment schema validation via Zod in `backend/config/envValidator.js` validating `NODE_ENV`, `PORT` (with safe number coercion and 5000 fallback), `MONGO_URI`, `JWT_SECRET` (>=32 chars prod / >=8 dev), `CRON_SECRET` (>=16 chars), and `ENCRYPTION_KEY` (32-byte base64 string for AES-256 TOTP).
- Step 1.4: [AUD-PERF-002] Realigned Expenditure compound index sort direction to `{ user: 1, date: -1, _id: -1 }` in `backend/models/Expenditure.js` and applied idempotent migration `backend/migrations/20261015_210000_aud_perf_002_realign_expenditure_index.js` after verifying database backup snapshot.
- Step 1.5: [AUD-SEC-002] Eliminated hardcoded cron fallback secret in `backend/middleware/cronAuth.js`, enforced constant-time comparison via `crypto.timingSafeEqual`, and added dual-header support for `x-cron-secret` and Vercel Cron `Authorization: Bearer <token>`.
- Step 1.6: [AUD-SEC-007] Installed and mounted Helmet middleware in `backend/server.js` (`crossOriginResourcePolicy: false`) enforcing modern HTTP security headers (`nosniff`, `SAMEORIGIN`, `Referrer-Policy: no-referrer`).
- Step 1.7: [AUD-SEC-009] Mounted `authRateLimiter` middleware on `POST /api/auth/refresh` and `POST /api/auth/2fa/disable` in `backend/routes/auth.js` enforcing rate limits (HTTP 429 on 11th request/min).
- Step 1.8: [SIMP-001] Purged abandoned legacy paycheck CRUD subsystem files (`AddPaycheck.js`, `EditPaycheck.js`, `PaycheckForm.js`, `PaycheckListPage.js`) after verifying zero imports, zero route bindings in `App.js`, and clean production build.
- Step 1.9: [SIMP-005] Standardized duplicate route aliases: added permanent HTTP 308 redirect from `/api/salary-profile` to `/api/salary-profiles` in `backend/server.js` and standardized frontend legacy aliases (`/salary-profile`, `/paycheck-log`, `/trades/new`) to canonical paths via `<Navigate replace />` in `frontend/src/App.js`.

### Security & Hardening - Phase 2A: Auth & Session Hardening
- Step 2A.1: [AUD-SEC-001] Enforced Role-Based Access Control on singleton tax brackets by mounting `authorize(['admin'])` on `PUT /api/tax-brackets` in `backend/routes/taxBrackets.js`, blocking non-admin (`manager`/`viewer`) privilege escalation and unauthorized modification of global system tax configuration.
- Step 2A.2: [AUD-SEC-003] Eliminated privilege escalation and mass assignment vulnerabilities on profile updates by making `updateProfileSchema` `.strict()` in `backend/validationSchemas/userSchemas.js`, enforcing an explicit field whitelist in `backend/routes/users.js` (`PUT /api/users/profile` and `PUT /api/users/:id/profile`), and adding upfront uniqueness checks returning HTTP 409 Conflict for `username`, `email`, `nationalId`, and `employeeId`.
- Step 2A.3: [AUD-SEC-004] Restricted CORS from permissive dynamic reflection (`origin: true`) to a strict whitelist matching `ALLOWED_ORIGINS` / `CLIENT_URL` (with localhost fallbacks in non-production) in `backend/server.js`, and hardcoded topology-derived cookie options with a 7-day maxAge in `backend/routes/auth.js`.
- Step 2A.4: [AUD-PERF-001] Replaced linear bcrypt scan in refresh token rotation with an indexed SHA-256 `tokenHash` ($O(1)$ lookup), enforced strictly cookie-only refresh and logout, implemented a 30-second delayed rotation grace window to prevent multi-tab logout storms, purged client `localStorage.refreshToken` across frontend services, and added migration `backend/migrations/20261015_211500_aud_perf_001_hash_refresh_tokens.js` (breaking change: all existing active sessions invalidated, requiring user re-login).
- Step 2A.5: [AUD-SEC-008] Reduced default JWT access token expiration lifetime from 30 days (`30d`) to 15 minutes (`15m`) in `backend/utils/tokenUtils.js`, bounding the exposure window of stateless authorization tokens.

### Security & Hardening - Phase 2B: Input & Query Defense
- Step 2B.2: [AUD-SEC-006] Eliminated MongoDB `$regex` injection and query crash vulnerabilities by implementing a centralized `escapeRegex` utility in `backend/utils/requestHelpers.js`, sanitizing user search inputs in `backend/routes/trade.js` and `backend/routes/realEstates.js`, and truncating search queries to 100 characters to prevent payload-size amplification.
- Step 2B.1: [AUD-SEC-005] ReDoS mitigation in Categorization Rule Engine & testing endpoint by adding pinned dependency `safe-regex@2.1.1` in `backend/package.json`, enforcing 150-char pattern cap and parser-hardened `safeRegex` validation inside Zod schemas (`createRuleSchema`, `updateRuleSchema`, `testRuleSchema`), capping `sampleText` at 1,000 characters, and protecting the interactive testing endpoint (`testRule`) with a 100ms `vm` timeout guard while leaving hot-path `matchesRule` overhead-free.
- Step 2B.3: [MF-SEC-002] Enforced atomic multi-tenant scoping and eliminated IDOR / 403 ID enumeration oracles on asset mutations and liquidations in `backend/routes/certificates.js` (`POST /:id/withdraw`, `PUT /:id`, `DELETE /:id`), `backend/routes/golds.js` (`PUT /:id`, `DELETE /:id`), and `backend/routes/trade.js` (`PUT /:id`, `DELETE /:id`), ensuring cross-tenant asset requests return clean HTTP 404 Not Found and eliminating unscoped `findByIdAndUpdate` operations.

### Security & Hardening - Phase 2C: File, Export & Backup Surface Defense
- Step 2C.0: [MF-SEC-002] Remediated deferred multi-tenant IDOR vulnerabilities across `backend/routes/realEstates.js` (`PUT /:id`, `DELETE /:id`) and `backend/routes/creditCards.js` (`PUT /cards/:id`, `DELETE /cards/:id`, `POST /transactions`, `GET /transactions/:cardId`, `PUT /transactions/:id`, `DELETE /transactions/:id`, `GET /transactions/due/:cardId`, `POST /payments`, `GET /payments/:cardId`, `PUT /payments/:id`, `DELETE /payments/:id`, `POST /payments/full`, `POST /payments/partial`, `GET /statement-cycles/:cardId`, `POST /reconcile/:cardId`), eliminating `403 Forbidden` vs `404 Not Found` resource enumeration oracles and replacing unscoped `findByIdAndUpdate` calls with atomic tenant-scoped queries returning clean `404 Not Found`.
- Step 2C.1: [MF-SEC-006] Implemented in-memory streaming MongoDB backup export (EJSON with relaxed: false and multi-sheet XLSX) and local development-only import engine (`/api/admin/backup`). Production and serverless environments strictly disable import (HTTP 501 Not Implemented). Implemented atomic collection replacement via MongoDB replica set transactions with staging collection swap and index preservation fallback on standalone topologies. Enforced whitelist validation, blocked collections (`refreshtokens`, `loginaudits`), lowercase casing normalization, and optional dry-run preview mode. Created admin frontend dashboard (`frontend/src/pages/admin/BackupPage.js`) with download selectors, file upload dropzone, dry-run delta diffs, and confirmation modal.
- Step 2C.2: [MF-SEC-008] Hardened bulk data extraction by introducing `/api/export/expenditures` and `/api/export/trades` endpoints with Mongoose cursor streaming (`.cursor()`) for memory efficiency, hard 5,000-row rejection cap (HTTP 400 Bad Request) to prevent memory exhaustion, atomic tenant scoping, and user-keyed rate limiting (5 export requests per 15 minutes per user).

- Step 3.1: [AUD-DATA-001] Implemented multi-document ACID transactional atomicity for credit card settlement flows in `backend/routes/creditCards.js` (`POST /payments`, `POST /payments/full`, `POST /payments/partial`), wrapping `CardPayment` creation, `CardTransaction` status and paid-amount mutations, `Expenditure` settlement generation, and balance propagation in `session.withTransaction()` with guaranteed `try/finally` session teardown (`session.endSession()`). Verified via unit test `backend/tests/unit/mwrrCashFlowDoubleCounting.test.js`.
